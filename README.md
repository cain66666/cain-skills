# cain-skills

> 📦 Живая коллекция скиллов для Cain и Claude-совместимых агентов. Пополняется по мере надобности — сюда добавляются проверенные, «очищенные» скиллы, готовые к установке одной командой. Public by design.

Контент-скиллы для Cain / OpenClaw / Hermes и любых Claude-совместимых агентов.
Чистые prompt-скиллы: без скриптов, без зависимостей, без API-ключей.

Закрывают полный путь статьи: **исследование → голос автора → письмо → стиль → проверка на ИИ → публикация.**

## Наши скиллы

| Скилл | Что делает | Команда | Или скажи словами |
|---|---|---|---|
| **voice** | Строит голосовой профиль автора по его настоящим текстам и ведёт его дальше. Главное — копит то, что автор **отвергает**. Режимы: setup / update / check. Любой язык. | `/voice` | «собери мой стиль», «обучи голосу», «это не мой голос» |
| **article** | Пайплайн статьи: каркас на одобрение → факт-лист → независимое письмо на каждом языке → стиль → гейт → сверка фактов → чеклист публикации. | `/article` | «напиши статью», «нужен лонгрид», «материал под поиск» |
| **gate** | Свежий читатель без контекста: писал человек или нейросеть. Судит по плотности приёмов, а не по списку слов. Показывает, не правит. | `/gate` | «проверь на ИИ», «читается как нейросеть?», «вычитай свежим взглядом» |
| **humanize-ru** | Очеловечивает **русский** текст: 52 паттерна, HARD BANS, quad-pass аудит. Режимы: полная правка / аудит / точечно. | `/humanize-ru` | «оживи текст», «убери следы ИИ», «звучит как робот» |
| **humanize-en** | То же для **английского**: фактурная конкретика, эмоциональный регистр, вариация ритма. | `/humanize-en` | «make this sound human», «remove AI-isms» |
| **story-ru** | **Русский.** Усиливает готовый текст как историю (12 приёмов + бизнес-модуль), правки в формате «Было → Предлагаю → Почему». | `/story-ru` | «сделай историей», «добавь нарратив» |
| **story-en** | **Английский.** Превращает плоское письмо или копирайт в историю по проверенным фреймворкам (Pixar spine, ABT, BAB, SCQA, StoryBrand). Режимы: hybrid (выдумывает, но помечает) и loose. | `/story-en` | «make this a story», «add a narrative» |

Слэш-команда у скилла ровно одна и совпадает с его именем. Всё из колонки
«или скажи словами» работает не как команда, а через понимание: агент читает описание
скилла и сам решает, что пора его применить.

## Исследование и аудит — в `seo/`

Девять скиллов для ресёрча: разбор запроса, бриф, семантические разрывы, кластеры тем,
аудит страницы, E-E-A-T, быстрые ответы, линкбилдинг, интервью с экспертом.

Это **форк набора [superseo-skills](https://github.com/inhouseseo/superseo-skills)**
от InhouseSEO под лицензией Apache 2.0. Мы взяли их исследовательскую часть как есть
и заменили половину, отвечающую за письмо, на свою. Подробности, лицензия и полный
список изменений — в [`seo/README.md`](seo/README.md).

Изобретать ресёрч заново незачем: у них он сделан хорошо, работает вживую (сам гуглит
и читает конкурентов) и не требует ни ключей, ни платных инструментов.

## Как складывается

```
keyword-deep-dive / content-brief     ← исследование (seo/)
              ↓
            voice                     ← один раз: профиль автора
              ↓
           article                    ← факт-лист → языковые версии
              ↓
  humanize-ru / humanize-en           ← стиль по языку
              ↓
             gate                     ← свежая сессия: человек или ИИ
              ↓
          публикация
```

**story-ru** и **story-en** стоят особняком: это не звено цепочки, а отдельная пара для
других форматов — постов, сценариев, писем, продающих текстов. Работают и по статье,
если нужен нарратив, но родной их жанр — короткий. Ставятся перед стилевым скиллом:
сначала усилить историю, потом убрать следы ИИ.

## Что звать в какой ситуации

**Один раз в начале.** `/voice` — собрать паспорт голоса. Понадобятся настоящие тексты:
переписка, письма, расшифровки голосовых. Итог — файл `voice-profile.<язык>.md` в проекте.
Дальше его читают все остальные скиллы.

**Статья под поиск — полный круг:**

```
/keyword-deep-dive «запрос»   → разбор выдачи, интент, конкуренты
/content-brief «запрос»       → бриф со структурой
/article                      → каркас        ⏸ ждёт вас
                              → факт-лист → версии по языкам
/humanize-ru или /humanize-en → стиль по языку
/gate  (в НОВОЙ сессии)       → вердикт       ⏸ ждёт вас
                              → публикация по чеклисту
```

Две остановки обязательны: после каркаса и перед публикацией. Всё остальное
переделывается дёшево, эти два — нет.

**Пост, рилс, письмо.** Конвейер не нужен: `текст → /story-ru → /humanize-ru` (по-английски: `/story-en → /humanize-en`).

**Проверить готовый текст.** Тут развилка:

| Что надо | Скилл |
|---|---|
| «что тут не так, я ещё правлю» — русский | `/humanize-ru`, режим аудита |
| «выпускать или нет» — финал, любой язык | `/gate`, **новая сессия** |

`humanize-ru` смотрит своим взглядом по каталогу из 52 паттернов. `gate` смотрит чужим,
без контекста, и считает плотность приёмов. На важном тексте прогоняют оба —
они ловят разное.

**Обновить вышедшую статью.** `/article`: сверить факты заново, править точечно,
прогнать гейт по изменённому, отправить на переобход.

**Только ресёрч, без письма.** Девять скиллов из `seo/` работают сами по себе:
`/page-audit`, `/eeat-audit`, `/semantic-gap-analysis`, `/topic-cluster-planning`,
`/linkbuilding`.

**Живой цикл голоса.** Каждый раз, когда правите текст со словами «я бы так не сказал»
— `/voice update`. Это то, ради чего профиль существует.

### Три вещи, которые легко сделать неправильно

**Гейт — только свежей сессией.** Агент, который писал текст, слеп к своим привычкам.
Гейт с контекстом одобрит что угодно.

**Каждому языку свой стилевой скилл.** Перекрёстно применять нельзя: длинное тире
в английском — маркер ИИ, в русском — нормальный знак препинания. Правила
противоречат друг другу.

**Языковые версии не переводятся.** `article` пишет каждую с нуля от факт-листа.

## Три вещи, которых обычно нет в других наборах

**Голос автора, а не усреднённый.** `voice` учится на настоящих текстах и, что важнее,
на отказах: каждое «я бы так не сказал» становится правилом. Через десяток статей
профиль знает автора лучше, чем он опишет себя сам.

**Многоязычность без перевода.** Каждая версия пишется с нуля от факт-листа, автор
одной не читает другую. Перевод тащит чужую грамматику, и читатель опознаёт это как
машинный текст. Правкой это не лечится — структура фразы уже задана чужим языком.

**Гейт отдельной сессией.** Правила внутри писателя не ловят то, к чему писатель слеп:
он повторил одну риторическую фигуру восемь раз и не заметил. `gate` читает готовый
текст без всякого контекста и считает **плотность приёмов**, а не запрещённые слова.

## Установка

```bash
git clone https://github.com/cain66666/cain-skills.git /tmp/cain-skills

# 1. Все скиллы одной плоской папкой. Cain (OpenClaw) читает её нативно.
mkdir -p ~/.agents/skills
cp -r /tmp/cain-skills/{voice,article,gate,humanize-ru,humanize-en,story-ru,story-en} ~/.agents/skills/
cp -r /tmp/cain-skills/seo/*/ ~/.agents/skills/

# 2. Симлинки для Claude Code и Hermes. Чего нет — пропускается.
for target in ~/.claude ~/.hermes; do
  [ -d "$target" ] || continue
  mkdir -p "$target/skills"
  for s in ~/.agents/skills/*/; do
    n=$(basename "$s")
    ln -sfn "../../.agents/skills/$n" "$target/skills/$n"
  done
done

# 3. Проверка: должно быть 16
ls -1 ~/.agents/skills | wc -l
```

**Почему так.** `~/.agents/skills` — один из штатных корней скиллов OpenClaw
(«Personal agent skills»), поэтому Cain находит их без всякой настройки.
Claude Code и Hermes смотрят в свои папки, туда ведут симлинки: правишь `SKILL.md`
один раз — обновляется везде.

Скиллы должны лежать **плоско**. Папка `seo/` в репозитории — только для порядка
и лицензии; при установке её содержимое раскладывается наравне с остальными,
это и делает вторая строка.

После установки начните новую сессию, чтобы агент подхватил скиллы.

## С чего начать

1. `/voice` — соберите голосовой профиль. Понадобятся ваши настоящие тексты: переписка,
   письма, расшифровки голосовых. Вылизанные лендинги не подходят, из них извлекается
   корпоративный голос, а не ваш.
2. `/keyword-deep-dive` или `/content-brief` — исследование по теме.
3. `/article` — первая статья. Скилл остановится дважды: после каркаса и перед
   публикацией. Оба раза ждёт вас.
4. Каждый раз, когда правите текст со словами «я бы так не сказал», — `/voice update`.
   Это то, что делает профиль рабочим.
